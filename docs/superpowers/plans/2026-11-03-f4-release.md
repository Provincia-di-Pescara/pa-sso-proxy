# F4 — Release

Spec: `docs/superpowers/specs/2026-11-03-ci-cd-security-baseline-design.md` §4 F4.

## Vincolo

Portainer riscarica `:latest` da solo: pubblicare = produzione. Ogni controllo prima dei tag;
nessun rebuild senza causa (riavvio inutile).

## Componenti

| File | Ruolo |
|---|---|
| `.github/workflows/release.yml` | unico workflow che pubblica: setup → build ×N → smoke-stack → publish ×N |
| `scripts/rebuild-check.sh` | cause a/b/c per immagine, JSON su stdout; controllo fallito = causa |
| `scripts/smoke-stack.sh` | compose di produzione con i digest, volumi vuoti, prima installazione via WebUI |
| `.github/workflows/docker.yml` | solo verifica in coda (build + smoke + Trivy), niente push |
| `.github/workflows/ghcr-cleanup.yml` | digest orfani, report finché `GHCR_CLEANUP_DELETE` non è `true` |
| `.github/workflows/security-alerts.yml` | issue + job rosso su alert code scanning high/critical aperti su main |
| `docs/deployment.md` | tag, rollback `latest-YYYYMMDD`, `cosign verify`, `gh attestation verify` |

## Scelte

- **Trivy differenziale** (nuova vs `:latest`, HIGH/CRITICAL con fix) sempre; **assoluto** solo sui
  tag (`satosa` CRITICAL, altri HIGH+CRITICAL). Causa c del rebuild-check limitata ai pacchetti
  di sistema (`--pkg-types os`): le CVE Python le corregge solo un commit (= causa a), altrimenti
  satosa verrebbe ricostruita ogni giorno per le HIGH del venv upstream.
- **Provenance/SBOM** come attestazioni GitHub (`actions/attest-build-provenance`,
  `actions/attest-sbom`, `push-to-registry`), non quelle di buildx (`provenance: false`,
  `sbom: false`): un manifest singolo per digest, verificabile con `gh attestation verify`.
- **cosign v3.1.4 keyless** (`sigstore/cosign-installer`, aggiunta all'elenco action consentite).
- **Smoke stack**: immagini ricostruite per digest + `:latest` attuale (per digest) per le altre =
  la combinazione che andrà in produzione.
- Tag `:main` non più prodotto (nessun consumatore noto).

## Verifica locale (fatta)

- `scripts/smoke-stack.sh` con le immagini della F3: tutti gli step verdi (Alembic head,
  login admin, impostazioni + cert SPID, satosa healthy dopo restart, discovery OIDC,
  metadata SPID firmato, nessun traceback).
- `scripts/rebuild-check.sh` sulle `:latest` reali: causa a corretta (commit F3), b e c vuote.

## Da fare dopo il merge

1. `gh workflow run release.yml -f dry_run=true` → controllare il summary delle cause.
2. `gh workflow run release.yml -f rebuild_latest=true` → prima release completa; verificare
   `cosign verify` e `gh attestation verify` su `:latest`.
3. Primo run di `ghcr-cleanup.yml` in report; se l'elenco è corretto e la DELETE è autorizzata
   (ruolo Admin del repo sui 3 package), impostare `GHCR_CLEANUP_DELETE=true`.
4. `harden-runner` in `block` nei job di build/publish: elenco host dai log DNS dei primi run
   (oggi `audit`).
